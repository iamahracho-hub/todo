# To-Do List 앱 — 요구사항 정리

## 1. 결정된 사항

| 항목 | 결정 |
|---|---|
| 플랫폼 | 웹 (브라우저) |
| 사용자 | 여러 사용자가 사용하지만 로그인 없음 |
| 데이터 저장 | 브라우저 localStorage (아래 근거 참고) |
| 추가 기능 | 카테고리/태그 + 검색, 마감일 + 우선순위 |

## 2. 데이터 저장 방식 — localStorage 추천 이유
"로그인 없이 여러 사용자가 사용"이라는 조건에서는 서버 DB에 사용자별 데이터를 구분해 저장할 방법이 없습니다 (로그인이 없으면 "이 데이터가 누구 것인지" 구분할 수 없음).
따라서 각자의 브라우저(기기)에 데이터를 저장하는 **localStorage 방식**을 추천합니다.
- 장점: 백엔드/DB 서버가 필요 없어 구축이 간단하고 빠름, 별도 회원가입 없이 바로 사용 가능
- 단점: 같은 사람이 다른 기기/브라우저로 접속하면 목록이 동기화되지 않음 (기기마다 별도 저장)
- 추후 여러 기기 동기화가 필요해지면 → 로그인 도입 + 서버 DB로 확장 가능

## 3. 최종 기능 목록

### 핵심 (필수)
- 할 일 추가 / 수정 / 삭제
- 완료 체크 (완료/미완료 표시)
- 전체 / 미완료 / 완료 필터
- localStorage 기반 데이터 저장 (새로고침해도 유지)

### 선택된 추가 기능
- **카테고리/태그**: 할 일을 업무·개인 등으로 분류
- **검색**: 제목/태그로 할 일 검색
- **마감일**: 날짜 설정, 임박·지연 항목 강조 표시
- **우선순위**: 높음/중간/낮음 등 설정 및 정렬

### 이번 범위에서 제외 (추후 고려 가능)
- 로그인 / 회원 관리
- 여러 기기 동기화
- 반복 일정 / 알림
- 다크 모드
- 협업 / 공유 기능

## 4. 기술 스택 제안
- **프론트엔드**: React (또는 간단하게 순수 HTML/CSS/JS도 가능 — 백엔드가 없으므로 어느 쪽이든 무방)
- **백엔드**: 없음 (모든 로직이 브라우저에서 동작)
- **데이터 저장**: 브라우저 `localStorage`
- **배포**: 정적 사이트 호스팅 (Vercel, Netlify, GitHub Pages 등) — 서버 없이 배포 가능

## 5. 데이터 모델 (초안)
```json
{
  "id": "uuid",
  "title": "할 일 제목",
  "category": "업무 | 개인 | ...",
  "priority": "high | medium | low",
  "dueDate": "YYYY-MM-DD",
  "completed": false,
  "createdAt": "ISO timestamp"
}
```
