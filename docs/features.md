# To-Do List 앱 — 기능 제안

## 1. 핵심 기능 (필수)
- **할 일 추가/수정/삭제**
- **완료 체크** (체크박스로 완료 표시, 완료 항목 구분 표시)
- **목록 조회** (전체 / 미완료 / 완료 필터)
- **데이터 저장** (새로고침해도 목록 유지)

## 2. 있으면 좋은 기능 (권장)
- **마감일(Due date)** 설정 및 임박/지연 항목 강조
- **우선순위** (높음/중간/낮음 또는 별표)
- **카테고리/태그** (업무, 개인, 쇼핑 등 분류)
- **검색 및 정렬** (이름순, 마감일순, 우선순위순)
- **순서 변경** (드래그 앤 드롭)
- **다크 모드**

## 3. 고급 기능 (선택)
- **반복 일정** (매일/매주/매월 반복되는 할 일)
- **하위 할 일 (서브태스크)** — 큰 작업을 작게 쪼개기
- **알림/리마인더** (브라우저 알림, 이메일 등)
- **여러 기기 동기화** (로그인 + 클라우드 저장 필요)
- **협업 기능** (다른 사람과 목록 공유)
- **통계/생산성 대시보드** (완료율, 주간 통계 등)
- **PWA / 모바일 앱화** (오프라인 사용, 홈 화면 추가)

## 4. 만들기 위해 결정해야 할 것들

### 플랫폼
- 웹 브라우저용인지, 모바일 앱인지, 데스크톱 앱인지

### 사용자 범위
- 나 혼자 쓰는 개인용인지, 로그인해서 여러 사람이 쓰는 서비스인지

### 데이터 저장 방식
- 브라우저에만 저장 (localStorage) — 간단하지만 기기 간 동기화 안 됨
- 서버/DB에 저장 — 여러 기기에서 접근 가능, 백엔드 필요

### 기술 스택
- 프론트엔드: React, Vue, 또는 순수 HTML/CSS/JS 등
- 백엔드(필요 시): Node.js, Python(FastAPI/Django) 등
- 데이터베이스(필요 시): SQLite, PostgreSQL, Firebase 등

### 디자인/UX
- 심플하고 미니멀한 스타일인지, 화려한 대시보드형인지
- 모바일에서도 잘 보여야 하는지 (반응형)

### 배포
- 로컬에서만 실행할지, 실제로 배포(호스팅)해서 어디서든 접속 가능하게 할지
